# 007: Permanent delete via fd-relative, identity-checked, single-filesystem removal
- Status: accepted (2026-10-23; rev 3: unfinished targets allowed per ADR-009; quit confirmation; aborted/partial delete → subtree rescan per plan D1)
- Context: M7 (confirm first; show path, size and counts; permanent; errors visible) and M9. A bug here destroys user data. Rust CVE-2022-21658 shows that check-then-act deletion is exploitable through symlink swaps. A plain recursive delete also descends into mount points inside the target.
- Options:
  - std::fs::remove_dir_all. Symlink-safe since 1.58.1, but it crosses mount points, does no identity check against scan data, and reports no per-entry progress.
  - Shell out to `rm -rf --one-file-system`. Coarse errors, no identity check, and runs an external process.
  - **Custom executor:** openat2(RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS) from the scan-root fd, a (dev,ino) check against the model, post-order unlinkat over dirfds, refusing to cross st_dev.
- Decision: Custom executor on its own thread, one delete at a time. The dialog confirms with `y` only; Enter, n and Esc cancel (UX). Rev 3: an unfinished target can be deleted. The dialog shows `≥` bounds, a "scan not finished" title and the 3 largest known children, and `p` prioritises its scan so the numbers become exact (ADR-009). Confirming cancels that subtree's scan. Refuse the scan root, aggregate tiles, and OTHER_FS nodes. The dialog shows a hard-link note computed from the hard-link table (files whose links are not all inside the target). The executor emits progress (files, dirs, bytes; ≤ 10 Hz) and a typed outcome with failures grouped by kind (permission, busy, read-only fs, other filesystem, other). Quit always needs a second confirmation. During a delete only `y` confirms (a double `q` does not). It then stops after the current entry and reports N of M on stderr. SIGTERM/SIGHUP do the same without a prompt. A mismatch aborts before anything is removed. Partial failures trigger a subtree rescan. After a delete, totals equal du on the remaining tree (tested).
- Consequences: About 200 LOC of safety-critical code, which needs a second reviewer. Kernel ≥ 5.6 is required for openat2 (the user runs 7.2).
- Blast radius / reversibility: The delete module; the effects are irreversible for user data by design (no trash, per the user).
- Revisit if: The user wants trash, multi-select, or concurrent deletes.
