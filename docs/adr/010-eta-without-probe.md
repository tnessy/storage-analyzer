# 010: ETA only from reliable sources; otherwise indeterminate progress
- Status: accepted (user approved, 2026-10-23)
- Context: Spike R3 (`spikes/r3-probe/REPORT.md`) measured the Knuth probe on 3 real roots with 100 seeds each. The **variant tested** picks a random child over all entries, so a descent ends at the first file. It is unbiased, but in most seeds it is 2-1000x low ($HOME: 96-98% of seeds <0.5x, median 0.001-0.005), with rare ~84x overshoots. ADR-005's revisit trigger fired. Brief M2 requires a labeled ETA that never shows a made-up number. The user's /home is btrfs (no inode counts), and history is off by default (user decision).
- Options:
  - Keep the probe, shown as a range or hidden until N%. Rejected: the range spans 2-3 orders of magnitude, and the estimate is usually below `seen` by 50%.
  - A `seen/(seen+pending_dirs)` percentage. Rejected: it is an upper bound on true progress, so it would always look optimistic.
  - A pending-dirs x mean-subtree estimator. Untested and likely low-biased under shallow-first. Optional spike R3b; not in v1.
  - Turn history on by default. Rejected: it reverses a user decision.
  - **Reliable sources only:** history (opt-in), an in-session previous scan (new, zero writes), the inode count (ext4/xfs mount roots). Otherwise an `Indeterminate` state showing only true quantities: elapsed, entries and bytes seen, rate, `≥ N folders queued` (an exact lower bound on remaining dirs), and `K of M top-level folders done`.
- Decision: The last option. The probe module, thread and `ProbeMsg` are removed. `EtaSource = History | SessionPrevious | FsInodes`. `EtaView` gains `Indeterminate`. No bar or `%` is shown without a source.
- Consequences:
  - **First scan:** with history off on btrfs, a first scan has no ETA, which is honest. M2's "revised as the scan proceeds" then holds only once a source exists, so project-owner should amend M2.
  - **Simpler build:** one less thread and module.
  - **Path to a real ETA:** the user gets one from `--history`, or from `r` on the root within a session.
- Blast radius / reversibility: eta (states), the status line (UX copy), T013/T019. Adding a future source is additive behind `EtaSource`.
- Measured follow-up (T002 rework, `spikes/r3-probe/REPORT.md`, 2026-10-23):
  - Variant B (subdirectory descent, X(v) = e(v) + s(v)*X(random child dir)) **fails** the pass rule.
    - K=256 median estimate/true: $HOME 0.07, /usr 0.35, node_modules project 0.63.
    - Better than variant A, but still far below 0.5-2x in most seeds on the user's real home.
  - Shallow-first `seen + pending_dirs`, simulated, is only a lower bound. It reaches 0.12 / 0.51 / 0.90 of the true total at 10 / 50 / 90 % on $HOME, with ETA error -0.92 to -0.99. That confirms it is unusable as a percentage or ETA, and it stays only as the guard and as the `≥ N folders queued` display.
  - **R3b is closed, not pursued.** The pending-dirs x mean-subtree estimator was not run directly. The BFS simulation shows pending folders hold most of the remaining work, and under shallow-first the completed subtrees that set the mean are the small ones, so the estimate would run low the same way. No v1 work.
- Revisit if: a new estimator (not variants A or B) is proposed and passes the same rule on the same three roots: within 0.5-2x at 50 % in ≥ 80 % of seeds at K=64, with no seed above 5x. Also revisit if the user wants a first-scan ETA enough to accept history on by default.
